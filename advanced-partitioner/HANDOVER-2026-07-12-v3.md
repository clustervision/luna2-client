  committed **ubuntu/x86 dracut 95luna module is ignored**. OPEN, fix identified: an
  **initramfs-tools hook** (`hooks/lpart` + local-premount installer) — a substantial port of the
  dracut luna2-start/luna-installer flow. Ubuntu lpart install has never worked e2e under the
  current luna despite the wired dracut tree.
- **Rocky 10**: the stock redhat build (`redhat/base.yml`) seeds the rootfs with the CONTROLLER's
  own release RPM (`rpm -qf /etc/os-release` -> el9), so `alternative_distribution=Rocky-10` gave
  an el9 rootfs. The stock cross-major route is a container source (`alternative_image_source=
  docker`, podman/docker absent here) -- but a container is NOT required: `dnf --installroot`
  bootstraps el10 natively from an el9 host by installing `rocky-release-10` + `releasever=10`
  against the (reachable) el10 BaseOS + trinityx/luna2 repos. FIX = parameterize base.yml's
  release-RPM + releasever (like ubuntu's `ubuntu_distribution_release` / opensuse's
  `opensuse_release`). Container-free. This is the preferred approach.
- **ubuntu build (debootstrap)**: EXTRA corrected across the session — needs
  `-e ubuntu_distribution_release=noble -e ubuntu_distribution_source=<mirror>` (NOT
